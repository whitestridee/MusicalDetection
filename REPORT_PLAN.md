# Что написать в отчёте

## 1. Постановка задачи

Нужно разработать сервис, который принимает аудиофайл-запрос и возвращает список наиболее похожих музыкальных композиций из базы данных.

## 2. Архитектура

Опиши пайплайн:

1. загрузка аудио;
2. предобработка;
3. извлечение признаков;
4. формирование embedding;
5. построение индекса;
6. поиск ближайших соседей;
7. возврат `Top-N` результатов.

## 3. Выбранный метод

Можно писать так:

- в базовой версии использованы спектральные и энергетические признаки;
- каждый трек переводится в фиксированный embedding;
- сходство между треками измеряется косинусной близостью;
- такой подход проще интерпретировать и реализовать, чем сразу использовать тяжёлые нейросетевые модели.

## 4. Почему метод разумный

- признаки отражают тембр и спектральную структуру аудио;
- усреднение по окнам делает представление фиксированной длины;
- косинусная близость удобна для сравнения нормализованных векторов.

## 5. Что показать в экспериментах

- поиск трека по самому себе;
- поиск похожего синтетического или реального фрагмента;
- влияние длины запроса на качество результата;
- примеры `Top-5` выдачи.

## 6. Что написать в разделе улучшений

- переход на нейросетевые embedding-модели;
- использование `FAISS` или `HNSW`;
- поддержка `mp3`;
- добавление веб-интерфейса и автоматической загрузки файлов.
